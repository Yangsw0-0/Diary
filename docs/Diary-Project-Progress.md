## 使用规则

M0–M7 任务状态使用“未开始 / 进行中 / 待验证 / 已完成 / 阻塞”；额外工作使用“待规划”，暂不考虑的平台工作不列为任务。只有达到表中的验收条件才标记“已完成”。完成一个任务组后，更新本页、运行相关检查、检查 Git 差异，再提交并推送到 GitHub 仓库。下面按依赖顺序安排工作，暂不承诺未经实测的日期和工期。

## 测试资料与风险

- 测试夹具放在 `tests/fixtures/`，只使用人工编写的示例 Markdown，不复制真实日记。
- 文件测试用临时目录，重点检查非法日期、路径逃逸、写入失败、revision 冲突和残留临时文件。
- UI 测试重点是中文输入法、连续保存、关闭前草稿、原位渲染、历史导航和滚动恢复。
- 附件测试重点是同名文件、复制失败、图片预览、普通附件及整目录迁移。
- 后续旧文件导入的格式与同日期冲突待脱敏样例确定。M6 附件限制为单个文件非空且不超过 20 MiB。
- GitHub 只管理程序代码和文档；日记根目录需要单独备份。
- Windows 使用 `\` 作为路径分隔符，日记内的附件链接仍固定为 `/`；测试同时覆盖两种平台的路径校验。Windows 安装包未签名，发布说明需保留 SmartScreen 提示。
