# M5 结构审查处理记录

依据用户提供的 M5 只读审查，逐项对照当前源码。此次只处理可复现的正确性问题和改动范围明确的性能问题；大型架构调整留待出现实际需求或性能证据时再实施。

| 建议 | 决定与理由 |
| --- | --- |
| 标签读取与保存竞态 | 采纳。查询开始记录索引版本；读取期间若索引变化，废弃本轮结果并有限重试。这样不会把旧正文与新索引混用，也不会在并发保存后执行旧的 `removeDay`。无需为每个日期引入独立版本或拆出一整套修复队列。 |
| 后退、前进和模块切换恢复小节 | 采纳。历史目标含小节时重新发出带日期的定位请求，编辑器只接收当前日记的请求；定位后再恢复该历史记录的滚动位置。 |
| 标签读取无界并发 | 采纳固定为最多 6 个并发读取。现有 IPC 尚无可取消的批量读取契约；取消信号可阻止后续任务启动和结果提交，已发出的读操作仍会完成。 |
| 同日期重复历史、滚动恢复覆盖手动滚动 | 采纳。点击当前日期不新增历史；滚动恢复前后比较滚动事件代数，用户已滚动则放弃预定恢复。 |
| 覆盖保存后的选中校验、历史上限 | 采纳。覆盖保存前检查导航序号与日期，保存后再次核对选中日期；并发导航可以等待已提交的保存完成。历史最多保留 200 条。更换根目录现由 AppShell 重新挂载导航实例，历史自然清空；额外 `clear()` 暂无调用场景。 |
| 标签面板每次键入重渲染 | 部分采纳。标签面板只订阅“有未保存修改”布尔值及索引版本，详情只计算一次标签分组。日记列表仍订阅完整会话；是否需要切片或虚拟列表，留待大数据量实测。 |
| 模块级 `FeatureNavigator` 与拆分 `useAppNavigation` | 暂缓。当前仅有日记和标签两个页面，M6 的附件属于日记编辑流程，并无第三个页面。现在引入通用激活、捕获、焦点协议会扩大状态同步面，且不能直接解决上述两项行为问题。将来新增独立模块时再从具体导航需求抽取接口。 |
| 启动只读摘要、Rust 或 Worker 建索引 | 暂缓。标签列表需要各日小节信息，单纯改为 `listSummaries()` 仍须读正文或维护可失效缓存。先完成 M6 的实际归档规模测试与启动耗时测量，再决定批量解析或后台工作线程。 |
| `TagService` 查询/修复拆分、`TagOccurrence` 移出领域层 | 暂缓。查询前核对磁盘 revision 是防止源码偏移错位的必要步骤；此次加入索引版本检查解决竞态。若订阅重跑或读模型边界成为实测问题，再拆分修复流程和类型。 |
| 编辑器原位替换 Markdown、ProseMirror 节点定位 | 部分采纳。明确编辑器由 `date:editorEpoch` 的 key 驱动重挂载，外部重载会重置光标及撤销栈。此处直接添加 `replaceMarkdown` 容易与现有草稿、撤销和保存回调相冲突。审查所称“真实 `focusSection` 未覆盖”与现有 `tests/crepe-editor.test.ts` 不符，该测试已实际挂载 Crepe 并检验重复标题定位；若将来更换节点定位方式，再补对应的集成验证。 |
| 结构化错误与冲突原因 | 暂缓。存储层已有 `DiaryError.code`，主要错误可展示并提供重载、覆盖或放弃动作。若出现无法区分的真实错误案例，再扩展 UI 错误状态和 IPC 元数据，避免仅为理论分类增加接口。 |

验证：新增标签读取与保存竞态、读取并发、导航小节恢复、同日历史和历史上限测试；`npm run check` 通过。原生 macOS 窗口的输入法、真实编辑器焦点与滚动行为仍列在 M6 手工验收。
