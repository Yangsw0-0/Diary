# M6 审查建议的处理记录

本记录针对用户提供的只读审查意见，按当前源码和 `v1.0.0` 仓库状态重新核对。审查文本中的优先级与发布状态是建议，不直接替代项目事实。

## 已采纳

- 附件导入、预览改用 Tauri raw IPC，避免 20 MiB 附件转成 JSON 数字数组；Rust 保留大小上限。
- 附件链接插入成功后消费请求，重新挂载编辑器不会重复插入。
- Rust 与 TypeScript 对损坏的侧栏宽度降级处理，工作区可继续打开；窗口变窄时钳制显示宽度。
- 标签图片的预览和失败状态按 URL 区分，切换图片不会沿用旧错误。
- 标签页普通链接交由系统打开，只允许网页和邮件地址；附件链接仍在选定日记目录内解析。
- 附件预览用禁止跟随符号链接的文件句柄读取，并限制实际读取字节数；硬链接不支持时用独占新建文件回退。
- 侧栏拖拽监听在组件卸载时清理。

## 已核对，无需重复修改

- 导航历史已为日记小节恢复生成 `focusRequest`；`back`、`forward` 和模块返回会使用目标视图的小节信息。
- `v1.0.0` 已打 Git 标签，M6 进度和发布记录已更新。审查中“尚未发布”的判断来自更早的快照。

## 暂缓

- 拆分 `DiarySession`、模块导航端口、标签修复流程重构、启动索引分批和订阅粒度优化：这些改动涉及数据流和并发边界。当前测试与实际归档规模尚无性能证据支持一次性重构；新增模块或出现可测量的延迟时再按具体瓶颈设计。
- 附件预览 URL 资源对象或引用计数：现有两个调用点均在卸载时撤销 `blob:` URL；本次修正了切换状态污染。引入全局引用计数会增加生命周期复杂度，待调用点增多再考虑。
- 普通附件打开前再做类型确认：现有文件只能从受控附件目录打开，并由用户明确点击。后续若支持自动打开或外部来源，再增加类型提示。

本轮界面改动同时解决侧栏动画、中间列表窄宽排版、目录名称显示和编辑器光标错位。编辑器缩放改为调整字体尺寸，正文排版宽度保持右侧面板的 80%。
