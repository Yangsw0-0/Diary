# Diary 节点功能工作计划（1.4.0 / 1.5.0 / 1.6.0 / M8）

## 最终需求与语义

用户最终确认：**一天一个节点，节点内允许多条事件**。本文件替代附件中“一天只允许一条事件”的旧限制。

- 左侧导航「节点」，全宽画布；上方日期时间轴，下方事件轮盘。
- 日期粒度为自然日，一个日期只有一个节点；每天可有多条事件。事件字段为概述、颜色、ID与审计时间，无正文、附件和日记关联。
- 同日添加自动追加；编辑日期移动单条事件到目标节点；移走/删除最后一条事件时移除空节点。
- 时间轴一天一个圆点，标签为日期和当日所有概述（省略、悬停全文）；选择日期聚焦其事件。轮盘按日期升序逐事件展示，同日按存储顺序。
- 六个纯自定义颜色槽位，无固定语义；事件只存槽位，色板修改即时影响同槽事件。
- 不实现搜索、筛选、批量操作、导入导出、云同步、打印。

## 数据与迁移

文件固定为用户选定目录根下 `Nodes.json`，UTF-8、两空格缩进、末尾换行。不进入仓库，不影响Markdown日记扫描和写作统计。

```json
{
  "version": 2,
  "nodes": [{
    "id": "node-uuid",
    "date": "2026-11-20",
    "events": [{
      "id": "event-uuid",
      "title": "值得纪念的时刻",
      "colorIndex": 0,
      "createdAt": "2026-11-20T00:00:00.000Z",
      "updatedAt": "2026-11-20T00:00:00.000Z"
    }]
  }]
}
```

验证：真实日历日、唯一日期、全局唯一非空ID、非空事件数组、1–60 Unicode字符概述、0–5整数颜色、有效ISO审计时间；最多1000个事件、4 MiB。忽略未知字段，缺字段不补默认值。日期升序；v1单事件模型集中迁移到v2，未知版本禁止编辑/覆盖。首次读取缺文件只显示空状态，首次实际保存才创建。

## 算法与交互细节

- 时间间隔改用 `64 + 24 * log1p(days)`。原附件的指数趋近在长跨度浮点运算下饱和，会使不同跨度得到相同值；对数函数在可用日期范围内严格递增。首节点从半屏宽处开始，内容宽度额外留半屏，使最早与最新事件都能滚到中央。
- 每个节点把「月.日」与事件标题分列轴线上下，并按节点奇偶交替；标签宽 64/216px、每侧两层，过密使用固定宽度省略，全文由 title 提供。只渲染视口外扩 280px 内的节点。轴线上按每个跨年边界画刻度，左侧旧年、右侧新年；无事件的年份也保留两个边界。引线为虚线。
- 轮盘 16° 步长；拖动除以 `R * STEP弧度`，而非直接把度数代入。边界最多 0.35 条弹性，松开取最近整数；转子约 280ms ease-out，减少动态效果时直接完成。卡片背景用模糊加水平遮罩模拟笔刷：左、上、下窄边渐隐，右侧 118px 长笔锋；卡片宽 `clamp(250px, 30vw, 520px)`。
- 一次只保留焦点附近±4条轮盘DOM；事件文字与色块随转子倾斜。日期顺序不循环。轮盘新增长指针（轴心/细线/箭头）与实线、虚线两道圆环装饰。
- 时间轴和轮盘共享 focusedId；拖动或触控板滚动停下后按最近节点更新焦点并居中。平滑居中触发的滚动不再反向改变焦点。聚焦不写盘，重启默认最新。
- 时间轴与轮盘之间的分隔线可拖动，时间轴最小 120px、轮盘最小 220px，最大不超过面板高度；键盘 ↑/↓ 微调，高度存 `diary.nodeTimelineHeight.v1`。
- 自动保存最后编辑后800ms，保存中编辑则完成后立即续存。revision二次校验紧邻原子发布；无覆盖新建使用硬链接，已存在使用同目录原子替换。
- 外部同步软件仍可能在最后检查与文件系统替换间竞态；不宣称对任意外部程序提供跨进程事务锁。
- 损坏恢复先尝试硬链接备份再删除原路径；硬链接不可用时退回同目录重命名，仍不覆盖原文件。覆盖正常文件必须用户明确确认。
- 色板键 `diary.nodeColors.v1`；浏览器localStorage与日记目录独立，不随Nodes.json迁移。
